# Telegram Utility Bot

Личный Telegram-архив на aiogram 3. Бот принимает текст, ссылки и Telegram-медиа в личном чате, сохраняет копию там же и даёт искать и разбирать сохранённое через одно редактируемое inline-меню.

## Запуск локально

1. Скопируй `.env.example` в `.env`.
2. Укажи `BOT_TOKEN`, свой Telegram ID в `ALLOWED_USER_IDS` и `OWNER_USER_IDS`.
3. Установи Python-зависимости: `pip install -r requirements.txt`.
4. Запусти `python main.py` или `Запустить бота.bat` в Windows.

## Развёртывание на Render

- Используй Web Service с runtime **Docker**; образ собирается из `Dockerfile` в корне проекта.
- Добавь значения из `.env` в Environment. Для безопасного доступа задай `ALLOWED_USER_IDS` и `OWNER_USER_IDS`.
- Локально OCR выключен, локальные зависимости не меняются. В Docker-образе для Render установлены Tesseract с языками `rus` и `eng`, Pillow и pytesseract; `ENABLE_OCR=1` включает ручное распознавание.
- Для уже созданного Web Service выбери Docker runtime в настройках Source/Build и запусти deploy. Сохрани `BOT_TOKEN`, `ALLOWED_USER_IDS`, `OWNER_USER_IDS`, `RENDER_FREE_MODE`, `DATABASE_PATH`, `HOST`; выставь `ENABLE_OCR=1`. `INSTALL_MEDIA_DEPS` больше не используется.
- `DATABASE_PATH` указывает на SQLite-файл. На бесплатном Render диск не постоянный, поэтому считай SQLite только рабочим индексом и оставляй Telegram-бэкапы в чате.
- Health endpoint: `/health`. UptimeRobot может раз в несколько минут обращаться к нему, чтобы будить бесплатный Web Service.
- OCR запускается вручную и может работать медленно на бесплатном тарифе.

## Как работает архив

- Отправленный в личный чат материал бот копирует в тот же чат, затем удаляет исходное сообщение. Если сохранить не получилось, исходник остаётся. Команды и временный текстовый ввод (например, название папки, запрос поиска или тег) удаляются после обработки, чтобы в чате оставались архивные копии и интерфейс бота.
- Перед сохранением бот проверяет повтор: для файлов сравнивает Telegram `file_unique_id`, для текста — нормализованный текст или ссылку. При совпадении повторную копию не создаёт и предлагает открыть уже сохранённую запись.
- Telegram хранит сами копии и файлы; SQLite на хостинге хранит индекс, папки, статусы, напоминания и ссылки на сообщения.
- Главное меню и списки редактируют одну закреплённую по `message_id` панель. Для просмотра медиа используется одно заменяемое превью.
- После потери SQLite бот не умеет перечитать историю чата через Bot API. Ответь `/restore` на последнюю резервную копию, чтобы вернуть каталог и связи с файлами.

## Резервные копии

- Автоматический снимок SQLite отправляется владельцу в этот же Telegram-чат; интервал `BACKUP_INTERVAL_HOURS` ограничен 24–48 часами и по умолчанию равен 24 часам.
- Пустая база после перезапуска Render не затирает старую копию: сначала восстанови предыдущую командой `/restore`.
- Для ручного снимка отправь `/backup`. Не удаляй сообщение с файлом бэкапа.
- Для восстановления ответь `/restore` именно на сообщение бота с файлом снимка. Рабочая база будет заменена содержимым выбранного снимка.
- Это защищает каталог на момент последней копии. Записи, сделанные после неё, могут потребовать повторного сохранения, хотя сами сообщения с файлами остаются в чате.

## Меню и функции

- **Входящие**: новые материалы до разбора; можно разобрать их по одному, сразу выбрать папку или удалить запись, после чего откроется следующий материал.
- **Поиск**: поиск по тексту и сохранённым метаданным; кнопку «Поделиться из архива» можно нажать в личном чате, выбрать собеседника и найти материал прямо в его чате.
- **На потом**: отдельный список отложенных материалов.
- **Избранное**: быстрые закладки.
- **Папки**: создать папку кнопкой и разложить материалы.
- **Напоминания**: напомнить о материале позже.
- **Случайная находка**: открыть случайный материал из архива.
- **Ещё**: список всех файлов, OCR по запросу, RSS-ленты и помощь.
- Карточка показывает основные действия: статус, избранное и «Ещё действия». В дополнительных действиях доступны тег, напоминание, OCR, контекст и inline-поделиться.
- Удаление материала удаляет запись каталога, её контекст и по возможности архивную копию в Telegram. Telegram ограничивает удаление сообщений по времени; если старую копию удалить нельзя, она может остаться в чате.
- У сохранённой копии фото/файла кнопки «Переместить» и «Добавить тег» доступны сразу, без открытия карточки.
- Кнопка «Добавить контекст» сохраняет короткую заметку ответом на архивную копию в чате; контекст отображается в карточке и участвует в поиске.
- OCR запускается только кнопкой в карточке сохранённого фото; результат сохраняется вместе с записью.
- RSS/Atom-ленты проверяются примерно раз в 15 минут; публикацию можно сохранить вручную.
- Inline-поиск настраивается в `@BotFather` командой `/setinline`. В меню архива кнопка «Поделиться из архива» сама открывает выбор собеседника, а в карточке материала кнопка «Отправить в другой чат» сразу предлагает именно этот материал. После выбора результата Telegram отправляет его в открытый чат.

## Команды

- `/start` — открыть меню.
- `/help` — подсказка.
- `/status` — состояние бота, каталога и бэкапа.
- `/backup` — сделать снимок сейчас.
- `/restore` — восстановить базу в ответ на сообщение с бэкапом.

## Ограничения

- Доступ ограничивается Telegram ID из `ALLOWED_USER_IDS`/`OWNER_USER_IDS`.
- Telegram-копии — источник файлов; SQLite — индекс. Bot API не позволяет боту автоматически пересканировать старую историю чата.
- Резервирование раз в сутки оставляет окно, в котором новый индекс может потеряться при аварии. Сразу после важной большой загрузки можно вручную вызвать `/backup`.

## Если `/start` молчит

- Проверь логи Render: если команда пришла от пользователя вне allow-list, бот теперь пишет предупреждение про `ALLOWED_USER_IDS` и `OWNER_USER_IDS`; если polling стартовал, будет строка `Starting Telegram polling`.
- Если команда вообще не появляется в логах, проверь, что Web Service запущен и что не запущена вторая копия бота с тем же токеном. Telegram допускает только один активный long-polling процесс на токен.
- При старте приложение удаляет настроенный webhook, сохраняя очередь обновлений, потому что этот проект работает через long polling.
